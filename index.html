    Concepts & sources

    A machine holds hardware. A GPU accelerates math. A model is software plus learned numbers (weights). A container image packages software; Kubernetes groups running containers into Pods. Each Pod runs on one machine. A distributed model uses cooperating worker Pods across machines.

    This lab models dedicated or shared GPUs and a simple request queue. Sharing checks combined estimated memory and divides compute among active workloads. It omits real kernel execution, batching, autoscaling, production storage dependencies, and exact hardware performance. Changing a layout instantly is a teaching shortcut.

    Model cards show an assumed inference format: BF16/FP16 use roughly two bytes per weight; FP8 uses roughly one; MXFP4 compresses expert weights further. Working memory is extra. Reservations are approximate, evenly divided for teaching, and do not certify that a real serving engine supports the selected layout. CPU execution and hosted availability are conceptual; not every model or format is supported by every runtime or provider. Each request here uses one model; the search models are demonstrated separately, not as a complete RAG pipeline.

    BUILD IT UP, ONE STEP AT A TIME

    Start with the machine.

    1. Add one feature. Turn on App / API, then drag Qwen3-8B onto an empty GPU. Click “Track one request,” then use “Next layer” to follow it. You can also click a card, then its destination.
    2. Add software layers. Compare direct Linux programs, Docker containers, and Kubernetes. Toggle notebooks, Langfuse, or storage when you want them. Kubernetes also enables the GitOps and recovery options.
    3. Experiment with the hardware. Try the giant-model setup, change the number of machines, and slow their connections. Or turn up incoming requests and watch the queue grow.

    Click × next to a model on the hardware to remove that copy. Removing a distributed copy frees all its GPUs. Reset lab clears models, queues, traces, and layers back to eight empty GPUs. Click a placed workload to inspect or move it. Machine power switches let you explore failures. Try Busy platform for simultaneous traffic. Increase a workload’s demand to build a queue, then add a matching replica. Click a waiting card to follow it, or a Langfuse trace to inspect its timing. The hardware-only preset starts a fresh experiment.

    Hardware = the machines and chips.
    Software = the instructions and model files running on them.
